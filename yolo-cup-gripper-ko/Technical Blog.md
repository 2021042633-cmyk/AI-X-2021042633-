## 0. 프로젝트 개요와 역할

이 프로젝트에서는 Intel RealSense D435i의 적외선 화면에서 컵을 찾는 객체 탐지 실험을 진행했다. 장기적으로는 카메라가 물체의 위치를 찾고, 소프트 그리퍼가 그 물체를 잡는 과정에 연결하는 것이 목표다. 이번 블로그에서 다루는 범위는 컵 탐지 모델을 학습하고 카메라 화면에서 결과를 확인하는 단계까지다.

프로젝트의 질문은 다음 두 가지다.

1. 소량의 적외선 컵 이미지로 YOLOv8n이 컵을 탐지할 수 있는가?
2. 컵을 찾는 장면에서 손을 컵으로 잘못 판단하는 문제는 남아 있는가?

이번 실험은 작성자가 수행한 컵 이미지 촬영, 라벨링, 학습 실행, 결과 확인을 바탕으로 정리했다. 실제 팀 구성이 따로 있다면 제출 전에 구성원과 역할을 수업 등록 내용에 맞게 수정해야 한다.

## 1. 제안과 문제 정의 (Proposal)

### 1.1 주제 선정 배경

소프트 그리퍼는 물체를 감싸서 잡을 수 있지만, 잡기 전에 물체가 화면의 어디에 있는지 알아야 한다. 카메라와 그리퍼를 연결하려면 먼저 카메라 영상에서 목표 물체를 안정적으로 구별하는 단계가 필요하다. 이 프로젝트에서는 제가 사용 중인 RealSense D435i의 적외선 영상을 입력으로 삼아, 컵을 탐지하는 과정을 확인했다.

적외선 영상은 일반 컬러 영상과 표현이 다르다. 색상 정보가 거의 없고 물체의 밝기와 윤곽이 두드러지므로, 실제 카메라에서 얻은 화면으로 직접 데이터를 만들고 확인할 필요가 있다. 처음부터 여러 물체를 한꺼번에 분류하기보다 컵 한 종류부터 시작해 데이터 구성과 탐지 결과를 살펴보았다.

### 1.2 프로젝트 목표

이번 프로젝트의 목표는 다음과 같다.

- RealSense 적외선 화면에서 컵 이미지를 수집하고 `cup` 클래스로 라벨링한다.
- YOLOv8n으로 컵 탐지 모델을 학습하고 검증 지표를 확인한다.
- 학습 데이터 구성을 바꾸었을 때 결과가 어떻게 달라지는지 비교한다.
- 손이 컵으로 잘못 탐지되는 실제 오류 사례를 기록하고 한계를 분석한다.

이번 단계에서는 카메라 좌표를 로봇 좌표로 보정하거나, 탐지 좌표로 로봇을 자동 제어하거나, 실제 파지 성공률을 측정하지 않았다. 따라서 결과를 완성된 자동 파지 시스템의 성능으로 해석하지 않는다.

### 1.3 전체 진행 흐름

| 단계 | 진행 내용 | 기록된 결과 |
|---|---|---|
| 1. 영상 준비 | RealSense D435i 적외선 화면에서 컵을 촬영 | 적외선 컵 이미지 |
| 2. 라벨링 | 화면 속 컵 영역에 바운딩 박스를 지정 | 단일 클래스 `cup` |
| 3. 데이터 구성 | 학습·검증 이미지를 나누고 별도 촬영 그룹을 보류 | 초기 12장 학습·3장 검증, 이후 학습 16장·검증 3장 |
| 4. 모델 학습 | YOLOv8n, 입력 크기 640, 30 epoch 실험 | `objects`부터 `objects4`까지 비교 |
| 5. 결과 확인 | 검증 지표와 실시간 적외선 화면을 관찰 | mAP 지표, 손 오탐 사례 기록 |
| 6. 다음 단계 | 더 다양한 장면과 독립 평가를 준비 | 좌표 보정과 실제 파지 시험은 향후 과제 |

## 2. 데이터 수집과 구성 (Dataset)

### 2.1 촬영 장치와 라벨

데이터는 Intel RealSense D435i의 적외선 화면에서 준비했다. 촬영한 이미지에서 컵이 보이는 영역을 사각형 바운딩 박스로 표시했고, 사용한 클래스는 `cup` 한 종류다. 데이터는 일반적인 웹 이미지가 아니라 실제 프로젝트에서 사용할 카메라 화면을 중심으로 만들었다.

이전 촬영 기록에서 확인할 수 있는 적외선 화면과 학습용 데이터 시각화를 이 저장소의 `그림%28Figure%29/실험기록/`에 함께 첨부했다. 같은 화면을 중복 저장한 파일은 한 번만 담았다. 촬영 거리·각도별 장수와 전체 원본 데이터셋은 보존된 기록에서 확인되지 않으므로, 이미지별 조건 통계는 제시하지 않는다.

### 2.2 데이터 버전과 분할

실험 과정에서 데이터 구성을 몇 차례 바꾸었다. 확인 가능한 데이터 수는 다음과 같다.

| 실험 데이터 이름 | 학습 이미지 수 | 검증 이미지 수 | 데이터 구성에 관한 기록 |
|---|---:|---:|---|
| 초기 데이터 | 12 | 3 | 컵 한 종류로 시작 |
| 확장 데이터 | 16 | 3 | 학습 이미지 수를 늘림 |
| 별도 촬영 그룹 | 기록 미확인 | 기록 미확인 | 학습에 섞지 않고 별도 테스트용으로 남겼으나 평가 수치는 정리되어 있지 않음 |
| `objects4` | 정확한 총수 미확인 | 3 | 손만 보이는 적외선 배경 예시를 추가해 미세 조정 |

`objects4`에서 추가한 손 배경 이미지의 수는 남아 있는 기록으로 확인할 수 없어 숫자를 추정하지 않았다. 검증 이미지가 세 장뿐이므로, 검증 점수는 소규모 실험의 관찰값으로만 해석해야 한다. 별도 촬영 그룹도 실제 평가 수치가 없어 독립 테스트 성능으로 보고하지 않았다.

### 2.3 데이터 구성에서 고려한 점

객체 탐지 데이터에서는 이미지뿐 아니라 바운딩 박스의 위치와 클래스 이름이 함께 중요하다. 모델은 이미지에서 컵의 모양과 위치를 학습하므로, 컵이 화면에서 차지하는 크기와 위치가 달라지는 장면이 충분히 들어가야 한다. 또 컵이 없는 배경이나 손만 있는 장면을 모델이 접하지 못하면, 컵과 비슷한 윤곽을 컵으로 오인할 수 있다.

이 문제를 확인하기 위해 `objects4`에서는 손만 보이는 적외선 배경 예시를 추가했다. 다만 검증 세트가 작고 구성도 제한적이므로, 이 변경만으로 오탐 문제가 해결되었다고 말할 수는 없다. 더 넓은 환경에서 같은 변화가 재현되는지 별도 데이터로 확인해야 한다.

## 3. 모델과 실험 방법 (Methodology)

### 3.1 객체 탐지와 YOLOv8n

객체 탐지는 이미지 안에 어떤 물체가 있는지와 그 물체가 있는 위치를 함께 예측하는 작업이다. 결과에는 클래스 이름, 바운딩 박스, 신뢰도 점수(confidence)가 포함된다. 이번 실험에서는 Ultralytics의 YOLOv8n을 사용하고, 클래스는 `cup` 하나로 설정했다.

YOLOv8n은 비교적 작은 모델 변형이다. 이번 선택은 제한된 CPU 환경에서도 실험 과정을 실행하기 위한 것이며, 다른 모델보다 항상 우수하다는 뜻은 아니다. 실제 성능은 데이터의 양과 다양성, 라벨 정확도, 촬영 조건에 따라 달라질 수 있다.

### 3.2 기록된 실행 환경

| 항목 | 기록된 값 |
|---|---|
| 카메라 | Intel RealSense D435i |
| 입력 영상 | 적외선 영상 |
| 모델 | YOLOv8n |
| 입력 크기 | 640 |
| 학습 환경 | Intel Mac CPU |
| Python | 3.11.9 |
| Ultralytics | 8.3.40 |
| 주요 학습 횟수 | 데이터 비교 실험에서 30 epoch |

학습 배치 이미지와 터미널 실행 화면은 실제 저장 기록에서 가져왔다. 실험 폴더가 화면에 표시된 로그는 확인 가능한 범위에서 각 모델 기록과 연결했으며, 폴더가 보이지 않는 그래프는 별도 자료 목록에 원본 그대로 보관했다.

![실제 YOLO 학습 배치 시각화](그림%28Figure%29/실험기록/학습/train_batch121.jpg)

현재 압축본의 코드 파일은 실험 과정을 설명하기 위한 예시다. 원래 실험에서 사용한 전체 실행 파일과 원본 가중치가 포함되어 있는 것은 아니다. 따라서 코드 예시가 과거 실행 코드를 그대로 복원한다고 주장하지 않는다.

### 3.3 학습 및 확인 절차

실험은 다음 순서로 진행했다.

1. 컵을 적외선 화면에 두고 이미지를 촬영했다.
2. 이미지에서 컵에 바운딩 박스를 지정하고 클래스를 `cup`으로 기록했다.
3. 학습 이미지와 검증 이미지를 분리하고 클래스 설정을 준비했다.
4. YOLOv8n을 입력 크기 640으로 학습했다.
5. 각 실험의 검증 지표를 확인했다.
6. 학습 이미지와 별도 실시간 화면에서 컵 탐지 여부와 오탐 사례를 관찰했다.
7. 손 배경 예시를 추가한 `objects4`를 학습한 뒤 같은 방식으로 확인했다.

### 3.4 평가 지표

| 지표 | 의미 | 해석 시 주의점 |
|---|---|---|
| Precision | 모델이 컵이라고 표시한 탐지 중 실제 컵인 비율 | 손이나 배경을 컵으로 표시하면 낮아질 수 있음 |
| Recall | 실제 컵 중 모델이 찾아낸 비율 | 컵을 놓치면 낮아짐 |
| mAP50 | IoU 0.5 기준의 평균 정밀도 | 바운딩 박스 위치와 클래스 예측을 함께 평가 |
| mAP50-95 | IoU 0.50부터 0.95까지 여러 기준에서 계산한 mAP의 평균 | 더 엄격한 위치 기준도 반영 |
| Confidence | 한 예측에 대해 모델이 표시한 신뢰도 점수 | 전체 데이터셋 정확도와 같은 뜻이 아님 |

## 4. 결과와 분석 (Evaluation & Analysis)

### 4.1 실험별 검증 결과

| 데이터/모델 | 학습 횟수 | 검증 이미지 | mAP50 | mAP50-95 |
|---|---:|---:|---:|---:|
| `objects` | 1 epoch | 3 | 0.142 | 0.0496 |
| `objects2` | 30 epochs | 3 | 0.995 | 0.548 |
| `objects3` | 30 epochs | 3 | 0.995 | 0.454 |
| `objects4` | 30 epochs | 3 | 0.995 | 0.609 |

이 표는 서로 다른 데이터 구성에서 남아 있는 검증 기록을 정리한 것이다. `objects`, `objects2`, `objects3`의 폴더 이름과 지표는 저장된 터미널 로그에서 확인했다.

`objects2` 검증 로그에는 mAP50 0.995, mAP50-95 0.548이 기록되어 있다.

![objects2 검증 실행 기록](그림%28Figure%29/실험기록/학습/image_20261104-063250.png)

`objects3` 검증 로그에는 mAP50 0.995, mAP50-95 0.454가 기록되어 있다.

![objects3 검증 실행 기록](그림%28Figure%29/실험기록/학습/image_20261104-071604.png)

저장된 YOLO 학습 곡선과 정밀도-재현율 그림은 함께 보관했지만, 모든 곡선 파일의 실행 폴더명이 확인되지는 않아 특정 실험에 붙이지 않았다.

![정밀도-재현율 곡선](그림%28Figure%29/실험기록/평가/PR_curve.png)

`objects2`, `objects3`, `objects4`의 mAP50은 모두 0.995로 기록되었지만 mAP50-95는 각각 0.548, 0.454, 0.609였다. 더 엄격한 바운딩 박스 기준에서는 결과 차이가 보였다. 그러나 검증 이미지가 세 장뿐이므로, 이 차이를 일반적인 성능 향상으로 단정하지 않았다.

| 검증 이미지 | 3장 |
| 검증 컵 인스턴스 | 3개 |

Precision 1.000은 이 작은 검증 표본에서 컵이라고 표시한 예측이 모두 맞았다는 기록이다. Recall 0.659는 실제 컵을 전부 찾지 못한 경우가 있었다는 뜻이다. 표본이 세 장이기 때문에 이 숫자를 실제 사용 환경의 안정적인 성능으로 해석하기 어렵다.

### 4.3 실시간 화면에서 확인한 오탐

실시간 적외선 화면에서는 손을 컵으로 잘못 표시한 사례가 남았다. 확인된 한 사례의 confidence는 0.99였다. 신뢰도가 높게 표시되었다고 해서 예측이 반드시 맞는 것은 아니다. 이 사례는 모델이 학습하지 않은 손 모양과 적외선 배경을 컵처럼 해석할 수 있다는 점을 보여준다.

이후 손만 보이는 적외선 배경 이미지를 추가한 `objects4`를 확인했지만, 기록된 검증 지표만으로 손 오탐이 완전히 사라졌다고 볼 수는 없다. 이를 판단하려면 손만 있는 이미지, 컵을 가리는 손, 컵과 손이 함께 보이는 장면을 충분히 모으고, 각 조건에서 오탐 수와 미탐 수를 따로 계산해야 한다.

### 4.4 추론 속도와 실제 시스템 범위

이전 실시간 기록에서 모델 추론 시간은 프레임당 약 54.8-83.9 ms였고, 별도로 남은 검증 기록에는 이미지당 54.9 ms가 있었다. 실시간 속도는 컴퓨터, 카메라 입력, 화면 표시 방식에 따라 달라질 수 있다. 이 값은 카메라 프레임 획득부터 로봇 명령까지 포함한 전체 시스템 지연이 아니다.

현재 프로젝트에서는 탐지 결과를 로봇 작업 좌표로 변환하는 카메라 보정과 로봇 자동 이동을 완료하지 않았다. 따라서 추론 시간만으로 그리퍼가 실제로 빠르고 정확하게 물체를 잡을 수 있다고 결론 내리지 않는다.

### 4.5 결과 해석

이번 실험에서 얻은 핵심 관찰은 세 가지다.

1. 적은 수의 적외선 이미지에서도 검증 화면에서 컵이 탐지되는 결과를 얻었다.
2. 손 배경 예시를 추가한 `objects4`에서 기록된 mAP50-95가 앞선 `objects2`, `objects3`보다 높았지만, 세 장의 검증 이미지로는 안정적인 향상을 입증할 수 없다.
3. 실시간 화면에서는 confidence가 높은 손 오탐이 남아 있어, 데이터 다양성과 실제 장면 평가가 다음 단계에서 중요하다.

## 6. 결론과 한계 (Conclusion & Discussion)

### 6.1 결론

RealSense D435i 적외선 영상에서 컵을 탐지하기 위해 YOLOv8n을 학습하고, 여러 데이터 구성의 검증 기록과 실시간 화면을 살펴보았다. `objects4`의 기록에서는 mAP50 0.995, mAP50-95 0.609가 확인되었고, 동시에 Recall 0.659와 손을 컵으로 잘못 탐지한 사례도 확인되었다. 따라서 현재 단계는 컵 탐지 가능성을 확인한 초기 실험으로 설명하는 것이 적절하다.

이번 결과는 작은 검증 표본에서 얻은 수치다. 모델이 다양한 컵, 거리, 각도, 배경과 조명에서 같은 성능을 낸다고 볼 근거는 아직 없다. 높은 검증 mAP 하나만으로 손 오탐이나 실제 파지 성공을 설명할 수도 없다.

### 6.2 한계

- 검증 이미지가 3장으로 매우 적다.
- 손 배경 이미지 수와 촬영 조건을 확인할 수 있는 원본 데이터가 현재 정리본에 없다.
- 보류한 별도 촬영 그룹의 평가 수치가 기록되어 있지 않다.
- 손 오탐의 반복 횟수와 조건별 오탐률을 계산하지 않았다.
- 원본 이미지, 원래 학습 코드, 모델 가중치가 업로드 자료에 포함되어 있지 않다.
- 카메라-로봇 좌표 보정, 자동 제어, 실제 파지 성공률을 시험하지 않았다.
- 추론 시간은 카메라와 로봇을 포함한 전체 동작 지연이 아니다.

### 6.3 다음 단계

다음에는 컵의 위치와 거리, 배경, 적외선 밝기를 달리한 이미지를 더 수집하고, 컵이 없는 장면과 손만 있는 장면도 별도로 라벨링할 계획이다. 검증 세트와 분리된 촬영 그룹에서 컵 탐지율과 손 오탐률을 계산하고, 결과 화면을 함께 저장하면 모델의 실제 한계를 더 분명히 설명할 수 있다.

그 다음 카메라 좌표를 로봇 작업 공간에 맞추고, 컵 위치를 바꾸어 반복 파지 실험을 진행할 수 있다. 이때는 탐지 성공 여부뿐 아니라 로봇의 위치 오차, 파지 성공 횟수, 실패 상황을 따로 기록해야 한다.
